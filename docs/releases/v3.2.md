# Release Notes — v3.2

**Base:** `master` @ `aa6a32d`
**Release branch:** `release/v3.2`
**Date:** 2026-03-22
**Latest tag:** `v3.2-rc32`

---

## Summary

v3.2 is a major feature release that adds Discord support, claude-code agent adapter, a CD daemon with auto-rollback, per-agent model override, global agent config cascade, and significant runtime hardening across the master-agent stack. Late-cycle additions include Discord reply quality improvements (mermaid rendering, table formatting, markdown preprocessing), timezone-aware logging, and a simplified session management approach using `--continue`.

---

## New Features

### 1. Discord Frontend (`MASTER_FRONTENDS=discord`)

- Master now supports Slack and Discord simultaneously via `MASTER_FRONTENDS=slack,discord` (or either alone).
- Discord bot uses native Thread channels for conversation tracking: @mention creates a Thread, follow-ups inside the Thread are routed automatically without re-mentioning.
- Discord slash commands registered in the admin guild with full parity to Slack commands.
- Long replies (>8000 chars) sent as `.md` file attachments. Text file attachments from users are read and appended to the prompt.
- New env vars: `DISCORD_BOT_TOKEN`, `DISCORD_ADMIN_CHANNELS`.
- The original Discord setup guide (`docs/guides/discord-setup.md`) has been removed; Discord integration was dropped in a later release per ADR-0006.

### 2. Discord Reply Quality Improvements

- *Markdown preprocessing*: `#` headers converted to bold, `---` horizontal rules stripped (Discord does not render these).
- *Table formatting*: markdown pipe tables converted to fixed-width monospace code blocks. Tables already inside a code block are left untouched.
- *Mermaid diagrams*: ` ```mermaid ` code blocks rendered to PNG images via `mermaid.ink` and attached as files. Falls back to raw code block on render failure.
- *Chunk labels removed*: `[1/N]` labels on multi-part replies removed; responses go into threads where sequential chunks read naturally.
- Platform-specific formatting rules injected into global claude config via `AGENT_FRONTEND` env var (set by master on every dispatch).

### 3. Claude Code Agent Adapter (`--adapter claude-code`)

- `/master-agent-load` accepts `--adapter codex|claude-code` to select the agent backend per agent.
- `MASTER_DEFAULT_AGENT_ADAPTER` sets the system-wide default (default: `codex`).
- Separate command templates: `MASTER_CODEX_COMMAND_TEMPLATE`, `MASTER_CLAUDE_COMMAND_TEMPLATE`.
- Session management: master always invokes `claude --continue` (resumes the most recent session in the container). Falls back to a fresh create if the session is missing. Sessions persist across container restarts as long as the named volume `agent-workspace-<name>` is intact.
- Auth pass-through: `CLAUDE_CODE_OAUTH_TOKEN` (preferred), `ANTHROPIC_API_KEY` (fallback).
- Token/cost usage footer appended to every claude-code reply: `[in=X cache_hit=X out=X | ctx=X/200k (Y%) | cost=$Z]`. The percentage is suppressed when cache_read inflates the total beyond the context window.

### 4. Change Claude Model Without Restart (`/master-agent-set-model`)

Two mechanisms for switching the claude model on a live deployment:

**Option A — Global config file mount**
Set `MASTER_CLAUDE_CONFIG_DIR_PATH` to the host path containing the claude global config. Copied into every agent container at startup via the entrypoint into a writable `~/.claude/`. Edit `settings.json` on the host; change takes effect on the next agent container restart.

**Option B — Per-agent model override**
```
/master-agent-set-model <name> claude-haiku-4-5   # set
/master-agent-set-model <name>                     # clear (revert to default)
```
Persisted in `agents.json`, survives restarts. Injects `--model <model>` into the claude command at dispatch time.

### 5. CD Daemon with Auto-Rollback

- New `src/cd/` module: polls a container registry for new image digests, deploys via `podman-compose up --force-recreate`, health-checks, and auto-rolls back on failure.
- On daemon startup: force-recreates the master container (not just restart) to ensure fresh env and mounts from the latest compose config.
- Webhook notifications for daemon startup, deploy, rollback, and failure events to Slack and/or Discord. Cloudflare-protected endpoints supported via custom `User-Agent` header.
- `CD_ENV_FILE` is loaded into the daemon's own process so daemon-level vars (e.g. `CD_NOTIFY_*`) are visible regardless of how the daemon container is configured.
- CD env vars (including masked webhook URLs) logged at startup for diagnostics.
- New compose file: `docker-compose.cd-daemon.example.yml`.
- `gen-env.sh` script to generate `.env` from the current shell environment, including host timezone (`TZ`).
- See [`docs/guides/runbooks/cd-daemon.md`](../guides/runbooks/cd-daemon.md) for operator guide.

### 6. Global Agent Config Cascade (`MASTER_CODEX_CONFIG_DIR_PATH`, `MASTER_CLAUDE_CONFIG_DIR_PATH`)

- Master mounts the host claude config directory read-only into every agent container at `/run/secrets/master_claude_config`.
- Agent entrypoint copies it to writable `~/.claude/` on startup. If no mount is present, falls back to the config baked into the image at `/opt/codex-slack/config/claude-global/`.
- `MASTER_PROJECT_DIR` enables auto-detection: master looks for `config/claude-global/` relative to the project root and uses it if found, without requiring `MASTER_CLAUDE_CONFIG_DIR_PATH` to be set explicitly.
- Sample global config at `config/claude-global/` — includes `CLAUDE.md` (formatting rules) and `settings.json` (`AI_AGENT_NAME`, `autoCompact`).

### 7. Global Claude Agent Identity (`AI_AGENT_NAME`)

- `config/claude-global/settings.json` injects `AI_AGENT_NAME=Exit! agent` into the agent's environment.
- `config/claude-global/CLAUDE.md` instructs the agent to start every reply with `<AI_AGENT_NAME> says:` and to apply platform-specific formatting based on `AGENT_FRONTEND`.

### 8. Agent Env Passthrough (`AGENT_FRONTEND`, `AGENT_CHANNEL_ID`, `AGENT_ADAPTER`)

- Injected into every `podman exec` call so agent-side code and `CLAUDE.md` instructions know which frontend, channel, and adapter dispatched the prompt.
- `AGENT_FRONTEND` values: `slack`, `discord`.

### 9. Timezone-Aware Log Timestamps

- All log timestamps now use local time with timezone offset (e.g. `2026-03-22 22:14:05 +0800`), respecting the `TZ` environment variable.
- `gen-env.sh` auto-detects the host timezone and writes it to `.env` (`TZ=<zone>`), so containers inherit the correct timezone.

## Diagnostics & Logging

- Master logs all env vars at startup (`master.env <VAR>=<value>`, secrets masked).
- `master.git_env` — logs SSH auth sock and `GIT_SSH_COMMAND` being set.
- `master.repo_source` — logs resolved repo type (local/github/explicit).
- `master.checkout` / `master.checkout_done` — logs clone start and completion.
- CD daemon logs all `CD_*` env vars at startup, masking `*_WEBHOOK_URL` values.
- `router.claude_command_template`, `router.parse_response_*` — diagnostic logs for claude JSON output parsing.
- Log timestamps include timezone offset; respects `TZ` env var.

## Breaking Changes

- `podman-compose 1.3.0` (from apt) no longer supported — use `pip install podman-compose` (1.5.0+).
- `podman compose` shim (`podman compose ...`) is not supported as `CD_COMPOSE_BINARY` — use `podman-compose` (direct).
- Agents now receive `AGENT_FRONTEND`, `AGENT_CHANNEL_ID`, `AGENT_ADAPTER` env vars (injected automatically by master).
- `CLAUDE_CONFIG_DIR` is **no longer** set in the agent environment. The entrypoint now copies claude config to writable `~/.claude/` instead. Code or hooks that rely on `CLAUDE_CONFIG_DIR` being set must be updated.
- Claude session state file (`claude_session_state.json`) is no longer written. The `session_state_path` field on `ClaudeCodeDispatcher` has been removed. Session continuity is now handled via `claude --continue`.

## Migration Notes

1. Rebuild the base image — `claude` CLI is now included; older images will fail with `sh: 1: claude: not found` for claude-code agents.
2. Update `CD_COMPOSE_BINARY=podman-compose` if using the CD daemon.
3. If using the CD daemon, set `CD_ENV_FILE` to the path as seen from **inside** the daemon container.
4. Re-run `gen-env.sh` to pick up `TZ` and updated defaults. Or manually add `TZ=<your/timezone>` to `.env`.
5. Register `/master-agent-set-model` as a new Slack slash command in the app portal.
6. If you were relying on `CLAUDE_CONFIG_DIR` being set in agent env, switch to reading from `~/.claude/` directly (which is where the config now lives after entrypoint copy).
7. Delete any existing `claude_session_state.json` — it is no longer read or written.

**Precondition:** master container running, Slack admin channel configured.

1. Run `/master-agent-list` in admin channel.
2. **Expected:** response lists agents (empty list is fine: `No agents loaded`).
3. Run `/master-agent-load <name> <repo> <channel_id>`.
4. **Expected:** success response with `state=loaded`.
5. Run `/master-agent-start <name>`.
