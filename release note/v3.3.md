## Summary

v3.3 is a quality-of-life release focused on operational robustness and observability. Highlights: graceful shutdown drains in-flight agent dispatches before CD restarts master; live container state appears in `/master-agent-list`; a new `/master-agent-refresh-config` command pushes updated global Claude config to running agents without restart; Slack shows a ⏳ reaction while dispatching; Discord shows a typing indicator.

---

## New Features

### 1. Graceful Shutdown — Drain In-Flight Dispatches on SIGTERM

When the CD daemon deploys a new master image it sends SIGTERM via `compose up --force-recreate`. Previously this would kill any in-flight agent dispatch mid-reply.

- New `src/master/dispatch_guard.py`:
  - `in_flight_dispatch()` — sync context manager that increments a thread-safe counter on entry and decrements on exit.
  - `install_sigterm_handler(drain_timeout=300s)` — on SIGTERM: sets `shutting_down=True`, waits up to 5 minutes for all in-flight counters to reach zero, then `sys.exit(0)`.
  - `is_shutting_down()` — boolean guard so incoming messages are dropped early during the drain window rather than starting new dispatches that will be interrupted.
- Both Slack handlers (`on_mention`, `on_thread_message`) and all three Discord `on_message` dispatch paths are wrapped with `in_flight_dispatch()`.
- `docker-compose.master-agent.example.yml` now sets `stop_grace_period: 5m`, matching the drain timeout so compose waits before sending SIGKILL.
- `main.py` calls `install_sigterm_handler()` at startup.

The CD daemon itself requires no changes — it already relies on compose force-recreate; the extended grace period takes effect automatically.

### 2. Live Container State in `/master-agent-list`

`/master-agent-list` now annotates each agent entry with its live Podman container state:

- `container_state` — Podman's `State.Status` string: `"running"`, `"exited"`, `"created"`, or `"absent"` (container does not exist yet).
- `container_running` — boolean shortcut (`State.Running`).

State is fetched from `podman inspect` for each agent at list time. Agents that have never been started show `"absent"`.

### 3. Push Config to Running Agents (`/master-agent-refresh-config`)

Operators can now push updated global Claude config (CLAUDE.md, settings.json) to a running agent without stopping and restarting it:

```text
/master-agent-refresh-config <name>
```

- Runs a disposable `alpine` container via `podman run --rm` (same pattern as `/master-agent-refresh-auth`).
- Mounts the host config dir (`MASTER_CLAUDE_CONFIG_DIR_PATH`) and the agent's workspace volume, then `cp -r` the config into `/workspace/home/.claude/`.
- The agent picks up the new config on its next Claude invocation.
- Requires `MASTER_CLAUDE_CONFIG_DIR_PATH` to be configured on master; returns `ERR_RUNTIME_FAILED` if not set.
- Available on both Slack (`/master-agent-refresh-config <name>`) and Discord (`/master-agent-refresh-config` slash command).

### 4. Working Feedback Indicators

Users now see visual feedback while the agent is processing.

**Slack:**
- Both `on_mention` and `on_thread_message` add a ⏳ (`hourglass_flowing_sand`) reaction to the user's message immediately after accepting the dispatch.
- The reaction is removed in a `finally` block after the agent reply is sent (or on error), so it never stays permanently.

**Discord:**
- All three dispatch paths in `on_message` wrap `asyncio.to_thread(router.route_*)` with `async with channel.typing():`, showing Discord's native typing indicator while the agent is working.

## Diagnostics & Logging

- `master.sigterm_received in_flight=<N> drain_timeout_seconds=<N>` — logged when SIGTERM arrives.
- `master.drain_complete` — logged when all in-flight dispatches finish before timeout.
- `master.drain_timeout in_flight=<N>` — logged (warning) when drain timeout expires with dispatches still running.
- `master.sigterm_handler_installed drain_timeout_seconds=<N>` — logged at startup.
- `master.shutting_down dropping mention` / `master.shutting_down dropping thread message` / `master.shutting_down dropping discord message` — logged when a new message arrives during the drain window and is dropped.

## Migration Notes

1. **Compose file:** Add `stop_grace_period: 5m` to the master service in your compose file (already present in the updated `docker-compose.master-agent.example.yml`). Without it, podman/compose sends SIGKILL 10 seconds after SIGTERM, which may not give master enough time to drain.
2. **Discord slash command:** Register `/master-agent-refresh-config` as a new application command in the Discord developer portal (or via `tree.sync()` if using guild sync). No new Slack slash commands — `/master-agent-refresh-config` is routed via the existing Bolt command handler.
3. No schema changes to `agents.json`; no image rebuild required for this release.

## UAT / Regression Test Cases

### T1 — Graceful shutdown drains in-flight dispatch

**Precondition:** master running with a claude-code agent, SIGTERM can be sent manually (`podman kill --signal SIGTERM <container>`).

1. Send a prompt that triggers a long agent dispatch (e.g. "write a detailed essay").
2. While the dispatch is in progress, send SIGTERM to the master container.
3. **Expected:** master logs `master.sigterm_received in_flight=1`; dispatch continues and completes; agent reply is sent to user; master then logs `master.drain_complete` and exits cleanly.
4. **Expected:** no `master.drain_timeout` warning appears in logs.

---

### T2 — Shutting-down master drops new messages

**Precondition:** SIGTERM sent to master with one in-flight dispatch (from T1).

1. While master is draining, send another mention in a mapped channel.
2. **Expected:** master logs `master.shutting_down dropping mention`; no reply sent; no new dispatch started.

---

### T3 — `/master-agent-list` shows container state

**Precondition:** at least one agent loaded, one started.

1. `/master-agent-list` in admin channel.
2. **Expected:** response includes `container_state: running` for the started agent and `container_state: absent` or `exited` for a loaded-but-not-started agent.

---

### T4 — `/master-agent-refresh-config` pushes updated CLAUDE.md

**Precondition:** `MASTER_CLAUDE_CONFIG_DIR_PATH` configured; claude-code agent running.

1. Edit `CLAUDE.md` on the host (e.g. change the agent's reply prefix).
2. Run `/master-agent-refresh-config <name>`.
3. **Expected:** success response; no restart required.
4. Send a prompt to the agent.
5. **Expected:** reply uses the new config (updated prefix visible).
6. Verify with `podman exec <container> cat /workspace/home/.claude/CLAUDE.md` — shows updated content.

---

### T5 — `/master-agent-refresh-config` fails gracefully when not configured

**Precondition:** `MASTER_CLAUDE_CONFIG_DIR_PATH` not set on master.

1. Run `/master-agent-refresh-config <name>`.
2. **Expected:** error response `ERR_RUNTIME_FAILED: agent claude config source is not configured`.

---

### T6 — Slack ⏳ reaction appears and disappears

**Precondition:** Slack frontend active, agent running.

1. Send a mention or thread follow-up to the agent.
2. **Expected:** ⏳ reaction appears on the user's message immediately after the ack.
3. After agent reply arrives, **expected:** ⏳ reaction is removed from the user's message.

---

### T7 — Discord typing indicator during dispatch

**Precondition:** Discord frontend active, agent running.

1. Send a mention or follow-up in an active Discord thread.
2. **Expected:** Discord shows "Bot is typing…" in the thread while the agent processes.
3. After reply is sent, typing indicator disappears.

---

### T8 — Regression: existing UAT T1–T13 from v3.2 still pass

**Precondition:** full v3.2 configuration.

Run v3.2 UAT test cases T1 through T13. All should pass unchanged.
