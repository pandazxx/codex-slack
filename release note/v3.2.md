## What's New

### 1. Change claude model without restart (`/master-agent-set-model`)

Two complementary mechanisms for switching the claude model on a live deployment:

**Option A — Global config file mount**
Set `MASTER_CLAUDE_CONFIG_DIR_PATH` to a host directory (typically `~/.claude`). The directory is bind-mounted read-only into every agent container and `CLAUDE_CONFIG_DIR` is set accordingly. Editing `settings.json` on the host (e.g. changing `"model"`) takes effect on the next prompt dispatch — no restart needed.

```dotenv
MASTER_CLAUDE_CONFIG_DIR_PATH=/home/user/.claude
```

**Option B — Per-agent model override (slash command)**
A new slash command persists a model override in the agent registry:

```
/master-agent-set-model <name> claude-opus-4-5   # set
/master-agent-set-model <name>                    # clear (back to default)
```

The override is stored in `agents.json`, survives master restarts, and injects `--model <model>` into the claude command at dispatch time. Per-agent overrides take precedence over the global config file.

### 2. Fix: conmon container create error with podman-compose 1.5.0

`podman-compose 1.5.0` silently ignores `${VAR:?error}` syntax (variable-required enforcement) and resolves to an empty string. An empty `MASTER_SSH_AUTH_SOCK_PATH` produced a volume mount of `:/ssh-agent`, which caused podman to fail with:

```
container create failed (no logs from conmon): conmon bytes "": readObjectStart: expect { or n, but found ,
```

All `:?` replaced with `:-` in `docker-compose.master-agent.example.yml`. Volume fallbacks:
- `MASTER_SSH_AUTH_SOCK_PATH` → `/dev/null`
- `PODMAN_SOCKET_PATH` → `/run/user/1000/podman/podman.sock`

## Breaking Changes

None. All changes are backward-compatible. Existing `.env` files without `MASTER_CLAUDE_CONFIG_DIR_PATH` continue to work — the new env var is optional.

---

## Migration Notes

- If you generated `.env` with an older `gen-env.sh`, verify `MASTER_SSH_AUTH_SOCK_PATH` is present and points to a live socket. If it was omitted, add it manually or re-run `gen-env.sh` (the variable is now always emitted with `$SSH_AUTH_SOCK` as default).
- Redeploy the CD daemon to pick up the startup-restart behavior added in a prior release candidate.

## UAT / Regression Test Cases

### T1 — Baseline: master starts and slash commands respond

**Precondition:** master container running, Slack admin channel configured.

1. Run `/master-agent-list` in admin channel.
2. **Expected:** response lists agents (empty list is fine: `No agents loaded`).
3. Run `/master-agent-load <name> <repo> <channel_id>` with a valid public repo.
4. **Expected:** success response with `state=loaded`.
5. Run `/master-agent-start <name>`.
6. **Expected:** success response with `state=running` and container name.

---

### T2 — Regression: conmon volume mount error does not occur

**Precondition:** `MASTER_SSH_AUTH_SOCK_PATH` is NOT set in `.env` (intentionally absent).

1. Run `/master-agent-start <name>`.
2. **Expected:** agent starts (or fails with a meaningful error — not a conmon JSON parse error).
3. Check master logs — must NOT contain `conmon bytes "": readObjectStart`.

---

### T3 — Option B: per-agent model override via slash command

**Precondition:** agent loaded and started (T1 complete).

1. Run `/master-agent-set-model <name> claude-haiku-4-5`.
2. **Expected:** success response — `model set to 'claude-haiku-4-5' for <name>`.
3. Run `/master-agent-status <name> --full`.
4. **Expected:** registry JSON contains `"claude_model": "claude-haiku-4-5"`.
5. Send a prompt in the mapped channel.
6. **Expected:** master logs show the dispatched command contains `--model claude-haiku-4-5`.
7. Run `/master-agent-set-model <name>` (no model).
8. **Expected:** success response — `model cleared for <name>`.
9. Run `/master-agent-status <name> --full`.
10. **Expected:** `"claude_model": null`.

---

### T4 — Option A: global model via config file mount

**Precondition:** `MASTER_CLAUDE_CONFIG_DIR_PATH` set to a directory containing `settings.json`.

1. Set `settings.json` content: `{"model": "claude-opus-4-5"}`.
2. Restart master (required to pick up the new env var).
3. Send a prompt in a mapped channel.
4. **Expected:** master logs show agent env includes `CLAUDE_CONFIG_DIR=/run/secrets/master_claude_config`.
5. Edit `settings.json` on the host to `{"model": "claude-haiku-4-5"}` — **no restart**.
6. Send another prompt.
7. **Expected:** claude picks up the new model (verify via response cost/token profile or model confirmation prompt).

---

### T5 — Model override precedence

**Precondition:** T3 and T4 both configured (Option B model set, Option A config dir mounted).

1. Set `/master-agent-set-model <name> claude-sonnet-4-6`.
2. Set `settings.json` to `{"model": "claude-haiku-4-5"}`.
3. Send a prompt.
4. **Expected:** `--model claude-sonnet-4-6` appears in the dispatched command (Option B wins at command level; Option A is available as fallback for settings not covered by the command flag).

---

### T6 — Registry persistence across restart

**Precondition:** T3 complete with model set.

1. Restart the master container.
2. Run `/master-agent-status <name> --full`.
