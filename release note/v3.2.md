# Release Notes — v3.2

**Base:** `master` @ `aa6a32d`
**Release branch:** `release/v3.2`
**Date:** 2026-03-21

---

## Summary

v3.2 is a major feature release that adds Discord support, claude-code agent adapter, a CD daemon with auto-rollback, per-agent model override, and significant runtime hardening across the master-agent stack.

---

## New Features

### 1. Discord Frontend (`MASTER_FRONTENDS=discord`)

- Master now supports Slack and Discord simultaneously via `MASTER_FRONTENDS=slack,discord` (or either alone).
- Discord bot uses native Thread channels for conversation tracking: @mention creates a Thread, follow-ups inside the Thread are routed automatically without re-mentioning.
- Discord slash commands registered in the admin guild with full parity to Slack commands.
- Long replies (>4000 chars) sent as file attachments. Text file attachments from users are read and appended to the prompt.
- New env vars: `DISCORD_BOT_TOKEN`, `DISCORD_ADMIN_CHANNELS`.
- See `docs/DISCORD_SETUP.md` for full setup guide.

### 2. Claude Code Agent Adapter (`--adapter claude-code`)

- `/master-agent-load` accepts `--adapter codex|claude-code` to select the agent backend per agent.
- `MASTER_DEFAULT_AGENT_ADAPTER` sets the system-wide default (default: `codex`).
- Separate command templates: `MASTER_CODEX_COMMAND_TEMPLATE`, `MASTER_CLAUDE_COMMAND_TEMPLATE`.
- Claude sessions are persisted per-channel across prompts using `ClaudeCodeDispatcher`.
- Auth pass-through: `CLAUDE_CODE_OAUTH_TOKEN` (preferred), `ANTHROPIC_API_KEY` (fallback).
- Token/cost usage footer appended to every claude-code reply: `[in=X cache_hit=X out=X | ctx=X/200k (Y%) | cost=$Z]`.

### 3. Change Claude Model Without Restart (`/master-agent-set-model`)

Two mechanisms for switching the claude model on a live deployment:

**Option A — Global config file mount**
Set `MASTER_CLAUDE_CONFIG_DIR_PATH` to the host `~/.claude` directory. Mounted read-only into every agent as `CLAUDE_CONFIG_DIR`. Edit `settings.json` on the host; change takes effect on the next dispatch — no restart.

**Option B — Per-agent model override**
```
/master-agent-set-model <name> claude-opus-4-5   # set
/master-agent-set-model <name>                    # clear (revert to default)
```
Persisted in `agents.json`, survives restarts. Injects `--model <model>` into the claude command at dispatch time.

### 4. CD Daemon with Auto-Rollback

- New `src/cd/` module: polls a container registry for new image digests, deploys via `podman-compose`, health-checks, and auto-rolls back on failure.
- Webhook notifications for deploy/rollback events to Slack and/or Discord.
- Restarts the master container on CD daemon startup to pick up env changes.
- New compose file: `docker-compose.cd-daemon.example.yml`.
- `gen-env.sh` script to generate `.env` from the current shell environment.
- See `docs/CD_DAEMON.md` for operator guide.

### 5. Global Agent Config Cascade (`MASTER_CODEX_CONFIG_DIR_PATH`, `MASTER_CLAUDE_CONFIG_DIR_PATH`)

- Master mounts host config directories read-only into every agent container.
- Worker seeds them into writable agent locations during startup; repo-level `.codex/` and `.claude/` override on top.
- Allows shared default prompts, hooks, and model settings across all agents from one place.
- Sample global config at `config/claude-global/`.

### 6. Agent Env Passthrough (`AGENT_FRONTEND`, `AGENT_CHANNEL_ID`, `AGENT_ADAPTER`)

- Injected into every `podman exec` call so agent-side code knows which frontend, channel, and adapter dispatched the prompt.

## Diagnostics & Logging

- Master logs all env vars at startup (`master.env <VAR>=<value>`, secrets masked).
- `master.git_env` — logs SSH auth sock and `GIT_SSH_COMMAND` being set.
- `master.repo_source` — logs resolved repo type (local/github/explicit).
- `master.checkout` / `master.checkout_done` — logs clone start and completion.
- `master.run_git` / `master.run_git_ok` / `master.run_git_failed` — logs full git command, exit code, stderr.
- `router.claude_command_template`, `router.parse_response_*` — diagnostic logs for claude JSON output parsing.

---

## Breaking Changes

- `podman-compose 1.3.0` (from apt) no longer supported — use `pip install podman-compose` (1.5.0+).
- `podman compose` shim (`podman compose ...`) is not supported as `CD_COMPOSE_BINARY` — use `podman-compose` (direct).
- Agents now receive `AGENT_FRONTEND`, `AGENT_CHANNEL_ID`, `AGENT_ADAPTER` env vars (injected automatically by master).

---

## Migration Notes

1. Rebuild the base image — `claude` CLI is now included; older images will fail with `sh: 1: claude: not found` for claude-code agents.
2. Update `CD_COMPOSE_BINARY=podman-compose` if using the CD daemon.
3. If using the CD daemon, set `CD_ENV_FILE` to the path as seen from **inside** the daemon container.
4. Re-run `gen-env.sh` or manually add `MASTER_SSH_AUTH_SOCK_PATH` — required for volume mount (`:?` guard removed).
5. Register `/master-agent-set-model` as a new Slack slash command in the app portal.

## UAT / Regression Test Cases

### T1 — Baseline: master starts, Slack slash commands respond

**Precondition:** master container running, Slack admin channel configured.

1. Run `/master-agent-list` in admin channel.
2. **Expected:** response lists agents (empty list is fine: `No agents loaded`).
3. Run `/master-agent-load <name> <repo> <channel_id>`.
4. **Expected:** success response with `state=loaded`.
5. Run `/master-agent-start <name>`.
6. **Expected:** success response with `state=running`.

---

### T2 — Discord: bot responds to @mention and creates thread

**Precondition:** `MASTER_FRONTENDS=discord`, bot invited to server.

1. @mention the bot in a mapped Discord channel with a prompt.
2. **Expected:** bot creates a Thread from its ack message; agent reply appears inside the Thread.
3. Reply inside the Thread without @mentioning the bot.
4. **Expected:** reply routed to same agent automatically.

---

### T3 — Claude-code adapter end-to-end

**Precondition:** `MASTER_CLAUDE_COMMAND_TEMPLATE` set, `CLAUDE_CODE_OAUTH_TOKEN` or `ANTHROPIC_API_KEY` configured.

1. `/master-agent-load <name> <repo> <channel_id> --adapter claude-code`.
2. `/master-agent-start <name>`.
3. Send a prompt in the mapped channel.
4. **Expected:** reply includes usage footer `[in=X cache_hit=X out=X | ctx=X/200k (Y%) | cost=$Z]`.
5. Send a follow-up in the same thread.
6. **Expected:** session resumes (no context loss).

---

### T4 — Per-agent model override (`/master-agent-set-model`)

**Precondition:** claude-code agent loaded (T3).

1. `/master-agent-set-model <name> claude-haiku-4-5`.
2. **Expected:** success — `model set to 'claude-haiku-4-5' for <name>`.
3. `/master-agent-status <name> --full` → registry JSON shows `"claude_model": "claude-haiku-4-5"`.
4. Master logs for next dispatch show `--model claude-haiku-4-5` in the command.
5. `/master-agent-set-model <name>` (no model) → `"claude_model": null`.
